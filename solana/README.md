# H0.81 Capital on Solana: programs

Four Anchor programs (the `anchor-lang` / `anchor-spl` crates, built with `cargo build-sbf`; the Anchor CLI
is not used). Binding design: `docs/SOLANA-PORT.md`. Reference implementation: the EVM contracts in
`contracts/`. **Nothing here is deployed to any public cluster.** No program has an admin key, a pause or
upgrade logic; deployment makes each one immutable (see "Deploying", owner's explicit go only).

## Layout

```
solana/
  Cargo.toml                  workspace (programs/*), release profile with overflow checks
  programs/stipend_pool/      shielded pool: transact, grant, spend, delegate, pull_lender_share,
                              verify_proof / verify_disclosure / verify_stream, staging buffers
    src/generated/            verifying keys and Merkle zero hashes (npm run solana:vk; do not edit)
  programs/stream_loan/       loans against pledged stream allowances (port of StreamLoan.sol)
  programs/capacity_stake/    staked H081 buys desk and shielding capacity (port of CapacityStake.sol)
  programs/safety_pool/       H081 stakers insure stream-backed loans (port of SafetyPool.sol)
  scripts/                    WSL scripts: build-all.sh, keygen, private validators (start/stop)
  keys/                       LOCALNET program keypairs (gitignored; never used for a public cluster)
  target-so/                  built .so files, staking fixtures, test outputs (gitignored)
src/solana/                   TypeScript SDK (field, pda, program, buffer, ops, events, wallet, lender, token)
test/solana/                  e2e, pool, lending, staking (validator suites); events, consistency (unit)
```

Crates: `anchor-lang` 1.2.1, `anchor-spl` 1.2.1 (`token`, `token_2022`), `solana-bn254` 3.2.1
(alt_bn128 syscalls for Groth16), `solana-poseidon` 5.0.1 (`sol_poseidon`, BN254 x5, circom-compatible),
`solana-sha256-hasher` 3.1.0, `solana-keccak-hasher` 3.1.0, `bytemuck` 1. Toolchain: Rust 1.99,
cargo-build-sbf 4.4.0, Solana CLI / solana-test-validator 4.3.2 (WSL Ubuntu).

## Addresses inside the circuits: fieldOf

The circuits range-check addresses to 160 bits; Solana pubkeys are 256 bits. Every pubkey that enters a
circuit is mapped with

```
fieldOf(pubkey) = big-endian integer of sha256(pubkey bytes)[0..20]
```

for the asset (the SPL mint), `publicRecipient` (the wallet that owns the payout token account),
`lenderAddr` (a lender wallet or a stream_loan slot PDA) and the relayer. The programs recompute `fieldOf`
from the accounts they are given and never trust a client-supplied field value for an account.
`extDataHash = keccak256(ext bytes as staged) mod r`.

## PDAs and accounts

stipend_pool

| account | seeds | contents |
|---|---|---|
| Pool | `["pool"]` | zero-copy: `next_index u32`, `current_root_index u32`, `filled_subtrees [20][32]`, `roots [128][32]` (4,752 bytes; 128 roots like `ROOT_HISTORY_SIZE` of the EVM pool) |
| Buffer | `["buf", authority, seed u64 LE]` | `disc(8) authority(32) seed(8) len u32 bump u8` (53-byte header), then the payload |
| Nullifier | `["nf", nullifier 32 B BE]` | discriminator only; existence = spent |
| vault authority | `["vault_auth"]` | no account; signs for every vault and escrow |
| Vault | `["vault", mint]` | token account of `mint`, authority `vault_auth` (SPL Token or Token-2022) |
| Escrow | `["owed", mint, lenderAddr 32 B BE, loan_ref u64 LE]` | token account, authority `vault_auth`; lender shares that could not be delivered |
| event authority | `["__event_authority"]` | Anchor `emit_cpi!` signer |

stream_loan

| account | seeds | contents |
|---|---|---|
| Registry | `["registry"]` | `next_loan_ref u64`, `bump` |
| Slot | `["slot", loan_ref u64 LE]` | `loan_ref, lender, bump, funded, settled, asset, token_program, principal, repaid, min_remaining u128, min_rate u128, pledge_bps u16, expiry, agent_pk [32], funded_at i64, payout_to, stream_start` |
| Ledger | `["ledger", loan_ref u64 LE, mint]` | `loan_ref, mint, held, received, bump` |
| inbox | associated token account of the slot PDA for the mint | where the pool delivers every routed share |

A borrower pledges to `lenderAddr = fieldOf(slot PDA)` and `loanRef`. Repayment is credited by `sync`
(permissionless) from the inbox; `fund` holds whatever is already in the inbox (not repayment, like
`onPledge` which credits only while funded) and refuses to fund while the pool escrow of the slot holds a
share (the SDK pulls it into the inbox in the same transaction). `shortfall` counts the unsynced inbox and
the pool escrow of the slot as paid. Tokens anyone sends straight into a funded loan's inbox are credited
as repayment: they did reach the lender.

capacity_stake: `Config ["config", mint]`, vault `["vault", mint]`, `Stake ["stake", mint, owner]`.
safety_pool: `SafetyConfig ["safety", mint]` (with the accounted `assets`), vault `["vault", mint]`,
`Position ["position", mint, owner]`, `Cover ["cover", loan_ref u64 LE]` (one per loan across all mints).
safety_pool reads stream_loan's Slot, Ledger and inbox and the pool escrow directly (no CPI).

## Token destinations

A token account that is not bound by extDataHash must be the canonical associated token account of its
owner, otherwise the transaction submitter could pick any account the owner nominally holds (for example a
non-ATA account created with `InitializeAccount3(owner = slot PDA)`, which stream_loan never reads):

- public payout of `spend`: the ATA of `publicRecipient` (else `Recipient`);
- lender leg of `spend`: delivered only to the ATA of an owner whose `fieldOf` is `lenderAddr`, not frozen;
  anything else (missing, wrong owner or mint, not the ATA, frozen) goes to the escrow, so the lender leg
  never blocks a spend;
- `pull_lender_share` (permissionless): only to that ATA (`Lender` / `LenderAccount`);
- `transact` withdrawal and fee accounts and the `spend` fee account are bound by extDataHash.

The SDK additionally simulates a pledged spend and resubmits it without the lender account when the
lender's ATA cannot take a CPI transfer (Token-2022 required memos and the like), as `tryTransfer` does on EVM.

## Buffer flow

Proofs (256 B) plus public inputs plus encrypted memos exceed the 1,232-byte transaction limit, so every
proof-bearing instruction reads `borsh(Proof, Args, ext bytes)` from a staging Buffer:

1. `buffer_open(seed, len)` with the first chunk in the same transaction (account created at up to 10 KiB);
2. `buffer_grow(seed)` up to 8 per transaction, +10 KiB each, up to 96 KiB;
3. `buffer_write(seed, offset, bytes)` in 900-byte chunks, any order, in parallel;
4. the operation (`transact`, `grant`, `spend`, `delegate`, or `verify_*`) takes the buffer, decodes it
   and, for the pool operations, closes it to the payer. `buffer_close(seed)` abandons one.

`Proof` is `a` (G1, negated, 64 B) `b` (G2, 128 B) `c` (G1, 64 B), big-endian; the SDK encodes it
(`encodeProof`). The payer of an operation must be the buffer's authority.

## Build and test

From Windows (Node is only on Windows; the toolchain and validators run in WSL):

```
npm run solana:build     # WSL: solana/scripts/build-all.sh, all programs + localnet variants -> solana/target-so
npm run test:solana      # every Solana test file, each suite on its own fresh validator, then stops them
```

`npm run test:solana` (`scripts/solana-test-all.mjs`) runs, in order:

| suite | validator | config | files |
|---|---|---|---|
| pool | rpc 8999, ledger `~/stipend-ledger` | `vitest.solana.config.ts` | e2e, pool, events, consistency |
| loan | rpc 9099, ledger `~/stipend-loan-ledger` | `vitest.solana-loan.config.ts` | lending |
| staking | rpc 9199, ledger `~/stipend-staking-ledger` | `vitest.staking.config.ts` | staking (fixtures regenerated) |

Options: `--keep` leaves the validators running, `--only pool|loan|staking`. A missing validator or program
fails the run; a skipped test fails it too. Ports 8899/8900 belong to another project and are never used;
the scripts stop only validators matched by their own ledger path. Compute units measured by the suites
go to `solana/target-so/compute-units*.json` and are checked against budgets in the tests.
Single suites: `npm run test:solana:pool`, `npm run test:solana:loan`, `npm run test:staking`.

## Deploying (owner's explicit go only; not done)

Nothing below has been run against any public cluster. Mainnet comes only after an external audit and a
public trusted-setup ceremony.

1. Generate the real program keypairs offline (never the localnet ones in `solana/keys/`). Put their ids in
   every `declare_id!`, in `stream_loan/src/pool.rs` (`POOL_PROGRAM_ID`), in
   `safety_pool/src/stream_loan_view.rs` (`STREAM_LOAN_ID`, `POOL_PROGRAM_ID`) and in the SDK constants;
   `npx vitest run --config vitest.solana.config.ts test/solana/consistency.test.ts` must pass.
2. After the ceremony, regenerate the verifying keys (`npm run solana:vk`) from the final zkeys.
3. Build the production programs only: `stipend_pool.so`, `stream_loan.so`, `capacity_stake.so`,
   `safety_pool.so` (never `stipend_pool_probe.so` or the `*_fast.so` builds). Prefer a verifiable build.
4. Deploy each: `solana program deploy --program-id <program-keypair.json> --upgrade-authority <deployer> <name>.so -u <cluster>`.
5. Initialize (all permissionless): stipend_pool `initialize`, `create_vault` per mint; stream_loan
   `initialize`; safety_pool `init_pool` and capacity_stake `init_config` per H081 mint.
6. **Make every program immutable** by removing its upgrade authority, irreversibly:
   `solana program set-upgrade-authority <PROGRAM_ID> --final -u <cluster>`, then check that
   `solana program show <PROGRAM_ID>` prints `Authority: none`. This step runs only on the owner's explicit
   go; until then the deployer key can replace the program code, which the design does not allow in
   production.

Mint-level powers stay with the mint: a Token-2022 mint with a permanent delegate, a freeze authority or a
transfer hook can move, freeze or block vault balances. Only list mints whose authorities are acceptable.
